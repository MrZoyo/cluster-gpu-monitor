# 本地 PAI 实时原型

PAI 是可选模块，默认关闭。启用后，根页面显示裸金属与 PAI 两个入口；`#/baremetal` 保留原总览，旧 `#/cluster/...`、`#/host/...`、`#/gpu/...`、`#/ranking` 链接仍可使用。PAI 关闭时根页面保持原总览。

## 不使用 PAI

不需要任何操作：不创建 `config/pai.toml`，或其中保持 `enabled = false`，也不启动 PAI 采集器。此时页面与原裸金属版一致：根路径就是裸金属总览，没有双入口首页、顶栏的“裸金属 / PAI”切换和任何 PAI 链接；返回总览、用户排行切换都回到 `#/`；手动访问 `#/pai...` 会回到总览。出于安全，未启用时 Web 不注册任何 `/api/pai/*` 路由，这些地址都是普通 404，响应中不提 PAI；配置无效时同样保持关闭，不影响裸金属站点。改为 `enabled = true` 后需重启 Web 才会注册。前端把 404 及其他不可达情况都按未启用处理；只有接口返回 503（已启用但快照暂不可用）时才显示 PAI 模块及其错误。公开静态演示站也不导出任何 PAI 接口文件。

## 运行

需要现有 Python 环境和已配置身份的 PAI CLI。当前适配器使用 `pai-tui` 的通用 `api` 和 `resource quota get` JSON 接口，在 CLI v1.0.1 上验证。原型采集器支持 macOS/Linux，使用文件锁阻止重复启动。生产发行包尚未加入 CLI 安装和服务生命周期管理。

1. 将 `config/pai.example.toml` 复制为私有 `pai.toml`，填入账号、地域、工作空间和根配额，设置 `enabled = true`。
2. `cli_path` 指向现有 CLI；可用 `profile` 选择已有配置。凭证保留在 CLI 原有凭证机制中，不能填入 TOML、网页或示例。
3. 指定 `GPUMON_PAI_CONFIG` 后先运行一轮，再分别启动采集器和 Web：

```sh
export GPUMON_PAI_CONFIG=/absolute/private/path/pai.toml
export GPUMON_ROOT=/absolute/private/runtime
python -m gpumon.pai.collector --once
python -m gpumon.pai.collector
# 另一个终端设置相同的两个环境变量，再启动 Web
gpumon web --host 127.0.0.1 --port 8890
```

Web 只读独立 `pai.db`，不会启动云采集、导入凭证或向云端发请求。本地原型可以使用操作者现有 CLI 身份；同一操作系统用户下的两个进程不构成凭证权限隔离。生产需另配服务身份和操作系统权限，再验证最小授权。

## 数据与采集边界

- 每轮先核实 STS 账号与配置一致。仅调用身份、配额、节点、Pod、任务、用户用量和 CloudMonitor 只读接口。
- 正常每 120 秒启动一轮，最多两路并发；单请求默认 12 秒，每轮 100 秒、120 次调用。最多 8 页，每页 100 个资源或 1,440 个指标点。超限记为失败并保留上次成功值，不冒充完整覆盖。
- 连续两轮失败后改为 180 秒，两轮成功后恢复 120 秒。遇到限流停止发起新请求；CLI 不暴露 Retry-After，保守等待至少 600 秒，连续限流翻倍。
- 配额和节点目录缓存 300 秒，任务、用户、Pod 映射及指标随轮次刷新。下一次目录刷新发现新节点；原型尚未实现未知 Pod 的定向拓扑补查。
- 指标读取最近 10 分钟的 60 秒源点，按原始时间戳幂等去重，保留 24 小时。曲线查询以固定 120 秒桶返回均值、最大源点、最新值、样本数和覆盖率；迟到点可修订已有桶。桶最大值不是分钟内瞬时峰值。
- 独立库保存最近成功快照、每来源的获取/尝试时间、状态、错误类别，以及任务/Pod/GPU 原始维度的指标。云端响应先按字段白名单筛选，原始错误文本不会进入 API。任务额外保留闲时资源标记（UseOversoldResource）、调度、排队位置、优先级、排队原因与入队/出队时间；配额保留分配明细；节点只保留节点级的健康与绑定配额，不保存随查询配额变化的工作负载计数。
- 卡数按节点与卡号去重。父子配额不相加；申请、调度和物理卡映射分列。物理卡与指标仅在 Pod 的源 GPU 索引集合和 GPUIndexes 相符时关联，多任务共享卡保持未知。
- 历史曲线不回填当前物理节点或个人归属。个人身份来自任务 Owner/提交者，不使用 CloudMonitor 的主账号 userId。缺失值不转成 0，采集失败不表示云节点宕机。
- 计算、显存各自保存源采样时间；超过 600 秒或来源失败的值标陈旧。未关联物理节点的 DLC/DSW 指标仍可在任务详情中查看。
- 主机 CPU / 内存利用率（DLC `POD_CPU_UTIL` / `POD_MEMORY_UTIL`，DSW `INSTANCE_CPU_UTIL` / `INSTANCE_MEMORY_UTIL`，占 Pod limit 的百分比）默认每 240 秒取一次，覆盖包括纯 CPU 任务在内的全部运行任务；使用 10 分钟重叠窗口补读迟到点；持续中断或上游缺测仍可能留下空档。CPU、内存申请量取自任务列表，不额外调用。
- DLC 任务详情（`dlc job get`）只保留提交策略、潮汐开关、AIMaster、状态和各角色 Pod 规格，不保存环境变量、命令、代码或数据源。新任务首次出现时查询，之后每 6 小时刷新，排队任务每 10 分钟刷新，每轮最多 8 个。
- 节点 Pod 列表为空是有效结果（该节点没有 Pod），不再记为“源无数据”。
- 云监控最新一分钟可能尚未上报齐，后续轮次通过重叠回读尝试补齐；上报延迟与覆盖率以各来源实际采样为准，不保证固定延迟后全部卡数都有数据。
- 采集器持有一个长期写连接，避免最后一个连接关闭时删除 WAL/SHM 文件，导致 Web 只读连接偶发打开失败。
- 排行历史表 `usage_hour` 每任务每 UTC 小时一行，保留 32 天：仅用当轮成功读取且状态为 Running 的任务累计：调度卡数 / 申请 CPU / 申请内存 × 采集器观测到的运行秒数（间隔超过两倍降级周期只计上限，新任务最多回溯同样时长），以及计算、显存、CPU、内存的分钟点求和与计数（每轮从原始点重算最近 3 小时，迟到点会被纳入）。

## 页面

- 顶栏标题回首页，“裸金属 / PAI”分段按钮切换模块。PAI 页的状态灯取自已读取的快照，不额外轮询；点击展开来源明细。
- 首页两张平台卡片各自显示新鲜度、摘要和逐卡色块，不合并两边的统计。
- PAI 总览：未见 GPU 占用、已分配但近 10 分钟计算 <5%（拆分配额内 / 闲时，点击跳到按低负载排序的任务表）、需核对（写明类别，点击跳到对应位置）三项提醒，分配条和 KPI；物理卡热力图中数字为计算百分比，底部细条为显存百分比，虚线为未分配，斜纹为未知，琥珀圈为已分配且近 10 分钟计算均值 <5%（至少 5 个分钟点；卡上数字仍为最新一分钟）。其下为用户、配额和任务。节点、任务、用户页提供筛选、搜索、排序和详情；任务详情含单卡当前值、近 1 小时曲线（含均值线）和源维度明细。
- 配额面板的数字为配额资源上的实际分配 / 容量；条形按“本配额任务 / 子配额 / 父配额任务占用”三段显示，取自配额详情的 self / descendants / ancestors 分配量。每个配额下列出直接提交的用户及申请卡数、占用其节点的父配额任务，以及使用闲时资源的用户；配额行标出控制台“闲时共享”开关（本级和子级资源可否被闲时任务使用，子配额与上级相同时不重复标注）。配额内任务申请量与“本配额分配”不一致时只标记差异，不推断原因。
- 闲时资源（接口字段 OverSold）：已调度任务的 `UseOversoldResource=true` 标为闲时资源（排队任务尚无占用，不标）。闲时任务不计入配额用量，节点不公开、具体位置未核实，不与物理卡相加，也不算作“未关联”或用户口径冲突；页面在 KPI、任务、配额和用户中用虚线紫色单独列出。
- 节点显示所属子配额（`BoundQuotas`）及健康状态（`ReasonCode`、健康度）；`Recovering` 按文档显示为“自愈中”，`ReasonMessage` 只是平台返回的时间，不当作故障原因或恢复期限。健康异常的节点上仍有任务时，提示由提交者保存数据和环境后重启 DSW（DLC 为停止或迁移），以继续节点自愈；页面不代为操作。配额行显示绑定节点中可接新任务的数量。健康异常且仍有任务时提示自愈相关文档。
- 排队任务（`IsScheduled=false` 或状态为 Queuing / Pending）在所有 PAI 页顶部以横幅列出，任务表置顶。申请量超过配额容量、或单 Pod 规格超过已知节点规格时，结合已采集的提交策略提示当前配置限制；策略未知或允许闲时资源时保留不确定性。调度器代码只翻译已确认含义的几项，原始 `Code` / `Reason` 始终保留；排队超过 30 分钟单独标出。
- 配额、闲时资源、抢占、调度、DLC、DSW、节点自愈等概念旁直接链接阿里云帮助文档（中文界面用 help.aliyun.com，英文界面用国际站同名页面）。
- “排行”标签使用顶栏时间窗（其他 PAI 页是当前快照，不显示时间窗）。任务表增加 CPU · 内存列；任务详情显示提交策略、AIMaster、Pod 规格、CPU / 内存申请与利用率曲线。
- 排队判定结合提交策略和单 Pod 规格：选了“不接受闲时资源”且申请超过配额容量，或单个 Pod 卡数超过本配额节点单机卡数，标为“当前配置放不下”；策略为可接受 / 只接受或未取得时，只标“可能排不上”或说明需等闲时资源。
- 仅当节点 Pod 映射新鲜，且节点请求卡数不超过已关联卡数时，未关联的卡才显示为“未见占用”；否则保持未知。闲时任务的物理位置不公开、可能未计入节点统计，所以“未见占用”不等于可立即使用。
- “计算 <5%”按任务卡维度、近 10 分钟均值统计（与裸金属近期利用率一致），避免单分钟抖动；陈旧值保留显示但带标记，不参与该提醒。
- 120 秒自动刷新保留滚动位置、筛选和展开状态；正在输入搜索词时推迟刷新。

## 只读接口

仅在 `pai.toml` 中 `enabled = true` 时注册。

| 接口 | 内容 |
| --- | --- |
| `/api/pai/status` | 启用状态、来源健康、覆盖摘要 |
| `/api/pai/overview` | 当前快照与全部模块 |
| `/api/pai/nodes` | 节点、卡号、当前映射 |
| `/api/pai/workloads` | DSW/DLC、Owner、申请/调度卡数 |
| `/api/pai/users` | 用户配额用量与任务状态差异 |
| `/api/pai/metrics/series?workload_id=...` | 默认近 1 小时，最多 6 小时、20,000 个源点；达到上限返回 truncated |
| `/api/pai/ranking?window=24h` | 用户 GPU·小时（配额内按配额拆分、闲时资源单列）、按利用率加权的有效 GPU·小时、CPU 核·小时、内存 GiB·小时及平均利用率；窗口与裸金属相同，最长 1 个月 |

PAI API 延续现有站点的访问边界，不加入匿名 `/api/v1/gpu-summary`。原型只监听 localhost；任务列表不具备“每个用户只能看自己”的应用内 RBAC。

## 本版验收与后续

使用合成夹具验证分页、缺失值、失败保留、源时间去重、120 秒聚合、用户归属、只读数据库和默认关闭。浏览器检查双入口、旧模块、任务/用户下钻、语言、主题、手机布局，以及来源故障与切页请求隔离。

回归入口：`pytest -q tests/test_pai.py`、`node tests/frontend_security.js`。
安装 Playwright 后可运行 `node tests/browser_recovery.cjs`；可用 `CHROME_BIN` 指定已有 Chromium/Chrome。
浏览器回归自行启动临时 localhost 站点，使用合成 API 数据，覆盖 PAI 默认关闭、启用后的各页面，以及接口格式变化和加载失败时的恢复提示。可用 `SHOT_DIR` 将验收截图保存到仓库外。

真实资源标识、采集分母、调用日志和截图保存在部署方私有记录中。完整生产验收尚需：专用服务身份、凭证文件权限隔离、发行包中的 CLI 版本固定、systemd 资源限制、双库备份与回滚、小内存容量测量，以及物理卡关联缺口调查。GPU·小时为最长 32 天的观测估算，使用小时桶，边界可能包含不足一小时的额外数据；不作为计费账单。尚未实现更长期历史、每卡精确 GiB 或逐 PID 用户分账。

接口依据：[ListQuotaWorkloads](https://help.aliyun.com/zh/pai/developer-reference/api-paistudio-2022-01-12-listquotaworkloads)、[ListQuotas](https://help.aliyun.com/zh/pai/developer-reference/api-paistudio-2022-01-12-listquotas)、[DescribeMetricList](https://help.aliyun.com/en/cms/cloudmonitor-1-0/developer-reference/api-cms-2019-01-01-describemetriclist)。
