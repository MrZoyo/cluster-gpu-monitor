# GPU 响应慢时的采集保护

简体中文 | [English](ADAPTIVE_PROBING.en.md)

主机可登录而 `nvidia-smi` 阻塞时，页面显示“疑似过载 · GPU 响应慢”，主机仍计入在线。
这是对采集响应的判断，不能据此确定是多人抢占、驱动故障还是其他原因。

## 状态与页面

| health | 含义 |
| --- | --- |
| `online` | 主机心跳与 GPU 查询正常 |
| `overloaded` | 主机可达，GPU 查询慢、超时、仍被上一查询占用，或正在恢复 |
| `gpu_error` | 主机可达，但 GPU 查询明确报错或传输中断 |
| `offline` | 近期仍在尝试采集，但主机心跳已经过期 |
| `unknown` | 采集尝试本身已过期，或还没有任何观测 |
| `inactive` | 摘要 API 中的非 active 主机 |

总览、集群、主机、单卡页面与摘要 API 使用一致的主机状态。过载主机有橙色缓慢呼吸边框，
卡片有静态斜纹；恢复阶段显示“GPU 响应恢复中”。系统要求减少动态效果时禁用动画。
悬停主机或卡片可查看查询间隔与上次有效采样时间。主机详情还会直接显示说明。

GPU 查询失败后，旧数据只在“上次观测”提示中显示，当前值为 `null`；未知卡单独计入
`cards_unknown`，不计为空闲。进程查询失败时可以保留已经完整返回的 GPU 指标，但使用人
显示数据暂不可用，不把缺失进程当成无人使用。

## 时间与恢复

`settings.toml` 的 `[collector]` 新增以下配置；旧配置未填写时使用这些默认值：

```toml
gpu_slow_s = 10
gpu_timeout_s = 20
gpu_backoff_s = 60
gpu_recover_s = 5
gpu_recover_count = 3
```

- GPU 阶段耗时达到 10 秒或发生超时/错误后，仅该主机降频。
- 降频期间 GPU 查询开始时间至少相隔 `max(poll_interval_s, gpu_backoff_s)` 秒。
- 主机心跳继续按 `poll_interval_s`（默认 30 秒）执行。到 GPU 查询时间的心跳复用同一连接。
- 连续 3 次有效查询小于 5 秒后恢复正常频率；再次变慢或失败会清零恢复计数。
- 必须满足 `gpu_recover_s < gpu_slow_s <= gpu_timeout_s`。冷却时间与厂商识别结果持久保存，
  重启后恢复；运行中的调度使用单调时钟，落后时不补发历史查询。
- GPU 超时覆盖整个厂商探测、指标和进程查询阶段。远端先 TERM，2 秒后仍未退出则 KILL。
  外层 SSH 超时取 `max(ssh_total_timeout_s, ssh_connect_timeout_s + cpu_sample_gap_s +
  gpu_timeout_s + 5)`；默认参数为 34 秒。心跳轮省去 GPU 预算。旧的 20 秒配置不再截断
  20 秒 GPU 阶段的结果收尾。
- 心跳和采集尝试的过期窗口均为 `max(120, 4 × poll_interval_s)` 秒。采集器停止更新时是
  `unknown`，不能据此认定整批服务器离线。

每台主机最多一个采集任务；健康节点完成后立即写库，无需等待慢节点。仍遵守全局 SSH
并发数、输出大小和解析对象预算。大量慢节点可以占满配置的并发槽，此时仍可能延迟其他
节点的启动；保护不会突破全局资源上限。

## 远端依赖与互斥

目标节点需要 Bash、GNU coreutils（含 `timeout`）、`ps` 和 util-linux 的 `flock`。
缺少工具时保留主机心跳并报告 GPU 采集异常，不自动安装软件。

脚本经 stdin 执行，不保存脚本或遥测数据。它在 `${XDG_RUNTIME_DIR:-/tmp}/gpumon-$UID/`
保留一个私有的 `gpu-probe.lock` 文件；目录必须由采集账号拥有且权限为 0700。
查询进程继承锁描述符。若旧驱动调用未退出，后续探测取得锁失败便跳过查询，不堆积
`nvidia-smi`。不要在旧查询仍运行时删除这个锁文件或目录。

NVIDIA 常规采集只执行两次 `nvidia-smi`：一次 GPU 指标，一次计算进程；PID 映射复用第二次
的输出。未配置厂商且尚未成功识别时，保留一次实际厂商探测以兼容安装了多家工具的主机；
成功后缓存结果。已知厂商可在 inventory 显式填写 `vendor: nvidia`。

## 历史统计

只为真实 GPU 样本记录采样权重：取该次查询开始时的计划周期，并以上一有效 GPU 样本至
本次样本的间隔为上限。失败和只做心跳的轮次不补写 GPU/进程样本，不跨失败延长权重。
该值用于采样估算，不证明两次观测之间一直存在同一进程。

近期均值、5 分钟/1 小时聚合、历史均值与 GPU·小时使用权重。各指标分别保留有效权重，
`N/A` 不参与该指标的均值分母；原始样本数 `n` 继续保存。覆盖率的分母仍是清单预期卡数
乘完整时间窗，分子为有效观测权重。进程先按用户/卡/采样时刻去重；共享卡仍按原口径分别
计入各用户，不按人数分摊。排行继续按既有精度四舍五入。

旧样本和旧聚合没有新增权重时沿用原配置周期；不回填历史，也不重写旧数据库的观测值。
GPU·小时仍是趋势估算，失败轮次仍可能少记。

## 升级与回滚

本次数据库变更包括两张附加表和聚合表的可空权重列。`gpumon initdb` 或 collector 启动会
幂等创建/添加它们，不全表扫描、回填或重建索引。发布流程必须先备份数据库和配置，再用
新版本执行 `gpumon initdb`，随后启动新版本 Web 和 collector；Web 使用只读连接，不执行迁移。

回滚旧代码时移除旧配置解析器不认识的五个新增配置项。附加表/列可以保留，但旧版统计
不理解自适应权重，会重新按固定周期估算，因此跨版本比较需保留这个口径差异。
本功能不要求修改目标节点的账号、驱动设置或任务。
